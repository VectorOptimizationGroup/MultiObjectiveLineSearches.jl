API Reference

For the workflow, see Using a line search; for method options, see BackTracking.

MultiObjectiveLineSearches — Module

Multiobjective line searches with reusable preparation and in-place execution. See configure_linesearch, perform_linesearch! and BackTracking.

source
MultiObjectiveLineSearches.AbstractLineSearchMethod — Type

Supertype for line-search specifications. Extend configure_linesearch and perform_linesearch! to implement a method.

source
MultiObjectiveLineSearches.configure_linesearch — Function
configure_linesearch(spec, evaluate!, x::AbstractVector, Fx::AbstractVector;
                     derivative! = nothing, value_derivative! = nothing)

Prepare reusable method state and work buffers without evaluating objectives. Fixed options are converted to T = eltype(x); eltype(Fx) must equal T, a concrete floating type. Both prototypes must be finite and nonempty.

evaluate!(F, y) fills objective values and returns nothing or an error string. Optional derivative callbacks are described in Extending the protocol. See Using a line search for reuse and input requirements.

source
MultiObjectiveLineSearches.perform_linesearch! — Function
perform_linesearch!(search, x::AbstractVector, d::AbstractVector,
                    Fx::AbstractVector; maxstep=Inf, method_data...)

Run a prepared search and return a LineSearchResult. maxstep is a nonnegative upper bound on the step (Inf adds no restriction); other keywords depend on the method.

On success, copy the borrowed result arrays into the consumer state before another call. Inputs must not alias those buffers. See Using a line search for validation, acceptance and failure handling.

source
MultiObjectiveLineSearches.InitialStatic — Type
InitialStatic(; alpha=1.0)

Propose the same positive, finite step alpha on every search. A per-call consumer bound may restrict that initial trial; no previous step is remembered.

source
MultiObjectiveLineSearches.LineSearchResult — Type
LineSearchResult(success, alpha, reason, message, nfev, ndev,
                 iterations, x_trial, F_trial)

Search result with these fields:

  • success, alpha: acceptance flag and step; on failure, the step is diagnostic only.
  • reason, message: termination symbol and optional error detail.
  • nfev, ndev: value and directional-derivative requests.
  • iterations: step reductions for BackTracking.
  • x_trial, F_trial: borrowed work buffers; accepted data only on success.

Counts reset per search and increment before callbacks, including reported failures. A joint callback increments both counters once, even if one output is discarded. Reused data do not count again; work/cache inside callbacks is not tracked. Their sum is not a count of callback calls or computational cost. Copy accepted arrays before reuse; see Using a line search.
